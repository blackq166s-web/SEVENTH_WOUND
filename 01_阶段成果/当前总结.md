## 三、关键结论与方法

1. **架构选择正确，不必重做**：`update/render` 分离 + 数据表驱动，使 20 个 Perk、9 把武器能在 4000 行内成立。后续加内容只需扩数据表与 `sprites.js`。
2. **验证思路可复用**：`smoke.mjs` 用 DOM/Canvas Proxy 桩在 node 里跑 1.5 万帧，不需要浏览器就能抓运行时异常；`shoot.mjs` 用本机 Chrome 出真实截图。两者互补——前者验逻辑，后者验观感。
3. **机器人是平衡标尺**：完美瞄准 + 粗糙走位，90s 内 4 波 132 杀属合理区间；真人应更长。机器人跑关卡模式必死，说明关卡对"不会躲弹幕"的玩家偏难，这是设计意图还是问题，待定。
4. **历史踩坑（改代码前必读）**：
   - `randomWeaponDrop` 曾因排除当前武器后池子为空返回 `undefined` → `magSize(undefined)` 崩溃。已加空池回退，改动掉落逻辑时注意。
   - 加入 cam.zoom 后，鼠标世界坐标必须 `cam.x + (mouse.x - cam.ox) / zoom`；测试机器人不同步换算会偏移 30%，曾被误判成平衡问题。

## 四之三、世界观地基（S2 · 文档 v0.1，2026-10-21）

用户要求：按网文套路做"穿越到异世界地下城"的设定，作为角色/场景/武器/敌人设计的上游依据。

**设定主干**：地渊是一具正在消化的活体，趴在多世界裂缝交汇处，吞下东西后**再铸**。它以战斗为食，于是把吞下的死者重铸成敌人，逼活人继续打。主角陆沉（军械维修工、射击队落选）掉进来，金手指是**残响**——能读到死者的"手感"，所以捡任何枪都会用；代价是每读一次，人格被覆盖一点。长线悬念：出去的那个还是不是他。

**为什么这套设定值钱**：它不是散文，而是**能反向支撑机制的解释器**。

| 机制 | 设定解释 |
| --- | --- |
| 无限刷怪 | 地渊回收尸体再铸，敌人会以更结实的壳回来 |
| 封闭场地 | 竞技场是地渊的胃，胃壁不可穿越 |
| 24s 一波 | 地渊的呼吸（潮汐）——**数值照抄现有 `waveTimer >= 24`，没改代码** |
| 每 5 波 Boss | 残响沉积压成守层者——照抄现有 `wave % 5 === 0` |
| 三选一升级 | 从残响中固化"刻印"（Perk） |
| 经验晶体 | 魔素结晶（地渊组织碎块） |
| 死亡重开 | 残响被记录，等待再铸 |

**结构性产出**（可约束后续所有内容设计）：
- 六层 = 六个器官，各有配色、生态、主导敌人、情绪目标；第六层的守层者是"上一任读完所有残响的人"，身上七道旧伤是自伤——Boss 因此必须人形、必须看得出曾经握枪。
- 九把武器按来源分三类：遗留（5）/ 再铸（3）/ 重火力（1）。规则：不允许"魔法杖"，地渊只改造不生产。
- 六敌人是同一具身体的六个部分，动作语言由器官角色决定。
- 20 Perk 分三条线：钢铁（8，借前人经验）/ 本能（7，身体被重铸）/ 侵蚀（5，借地渊之力）。**新增 Perk 必须归类并写代价**，这是防设定失控的闸门。
- 明写"不做什么"：无队友/NPC/城镇、无魔法、无救世主线、不解释穿越机制。

**文档位置**：`03_项目实现/docs/STORY.md`（设定）、`03_项目实现/docs/DESIGN_MAP.md`（映射 + A/B/C 改动分级 + `hud.js`/`game.js`/`ui.js` 具体行号的文案对照）。`docs/EXTENDING.md` 顶部已加硬约束，指向这两份。

## 四之七、P4 种子 RNG + 侵蚀值（2026-10-21）

P4 干两件事：先让数据可复现，再给"侵蚀"这条线补上代价。

**P4-0 种子 RNG：只换实现，不改调用**

`core/math.js` 加 `random()` / `setRng()` / `makeRng()`（mulberry32）/ `hashSeed()`。`random()` 默认就是 `Math.random`，所以**不传 seed 时行为与改动前完全一致**；`?seed=xxx` 才换成固定序列。

全库 32 处 `Math.random()` → `random()`：`game` 5 / `player` 2 / `enemies` 3 / `weapons` 3 / `camera` 2 / `sprites` 17。**只有 `core/audio.js` 的 2 处保留 `Math.random`** ——音频在"首次用户交互"时才初始化，时机不可控；如果它消耗种子流，同 seed 的结果会随交互时刻漂移。音效不参与数值，所以这个例外安全。

`start()` 里按 `this.seed` 重新播种，因此"重开一局"永远从序列头开始。

**P4-1/2/3 侵蚀值**

| 层 | 实现 |
| --- | --- |
| 累积 | `applyPerk` 判 `perk.line === 'erosion'` → `+8`，封顶 100 |
| ≥40 | 径向渐变红移（`0.18 + k*0.34`，随心跳搏动）+ 心跳音 1.15s→0.55s |
| ≥70 | 敌人移速 ×1.1（含已在场）+ 独白「这双手……不是我的。」「别再往里读了。」 |
| HUD | HP 条下方 5px 侵蚀条（0 时隐藏）+ 右侧 `侵蚀 N`，≥70 转红 |
| 结算 | 死亡面板「最高侵蚀」 |

**P4-4 验收（这是本轮唯一硬指标）**

```
node tools/determinism.mjs                    → DETERMINISM_OK（60s，三遍逐项一致）
node tools/determinism.mjs balance-2026 18000 → DETERMINISM_OK（300s）
两次独立进程 → 指纹同为 7c38ae31bed3ab08
反证：换 seed 结果不同 ✓ / setSeed(null) 恢复 Math.random ✓
```

比对的是 `kills / score / level / wave / hp / shots / damage / 敌人与子弹与拾取数量 / erosion / maxErosion / posHash`；`posHash` 是场上敌人位置与血量的加权和，专门防"总分一样但过程不同"。

**两个坑**

1. **红移第一版太淡**：侵蚀 45 时截图几乎看不出变化——渐变中段 alpha 只有 `a*0.35`，红全挤在最外圈。改成中段 `a*0.5`、基值 `0.18` 后，45 能看出泛红、100 明显但不影响读敌人。
2. **浏览器里验复现不能靠 `?auto&warm=N`**：warm 跑完后 rAF 还在推进，两次加载会差几帧，比对必然失败。正确做法是在 `evaluate` 里跑完固定帧数后立刻 `setState('paused')` 冻结世界再取指纹。

**结构调整**：把 smoke 里的 DOM 桩抽成 `tools/dom-stub.mjs`，smoke 与 determinism 共用，避免两份桩各自漂移。

## 四之八、发布 v0.2.0（2026-10-21）

**为什么要打包**：ES Module 在 `file://` 下被 CORS 拦住，所以"发给别人、双击就能玩"必须先内联。这是**发布需求**，不是开发需求——开发仍然直接跑 `index.html` + `src/`，一个构建步骤都不需要。

**做法**（`tools/pack.mjs`，零依赖，186 行）：从 `src/main.js` 做后序遍历拿到 18 个模块的拓扑序 → 每个模块包成 IIFE 注册进 `__mods`，`import` 变成从注册表取绑定 → 替换 `index.html` 的入口 script → 自检"还有没有外部依赖"。

```

PACK_OK 单文件无外部依赖，可直接双击打开
```

**版本号只有一个真源**：`package.json`。`index.html` 的帮助面板有 `#verLine`，`pack.mjs` 校验一致，不一致直接报错——避免"包是 0.2.0、界面写 0.1.0"这种低级错。

**顺手修的真 bug**：`game.js` 里 `localStorage` 是裸调用，在 `file://` 或隐私模式下会抛异常，导致整局起不来（白屏）。改成 `loadSave` / `saveBest` 两个 try/catch 包裹的函数——最高分丢了不影响玩，但这个异常会让游戏直接打不开。

## 四之十、S6-B 精灵重绘（2026-10-21）

**先立工具，再画**。三件工具决定后面每一只怪的上限：

| 工具 | 作用 |
| --- | --- |
| `shadeBody()` | 路径 → 基色 → 裁剪后叠「左上高光 / 右下暗部」→ 左上轮廓光 → 黑边 |
| `limb()` / `jointLimb()` | 锥形肢体、带关节的细腿 |
| `glowEyes()` | 带辉光的眼睛（最省力的"活物"信号） |

光源方向统一（左上），体积感不再靠"径向渐变球"硬凑。

**重绘清单**：玩家 72px（背包 + 八边形躯干 + 护胸板 + 外露的腿和靴 + 缠布条的左臂 + 不戴头盔）、腐化者（前倾、拖断腿、胸腔开口露肋骨、背后菌丝）、疾行者（四肢着地、脊椎外露、拖尾）、织网者（8 条腿 5+3 不对称、卵囊）、哨眼（独眼占半头、背部射口，后两帧蓄能发光）、融生体（三团粘一起 + 融进去的人手）、守层者（比例错乱、一只手臂是炮管、胸口七道旧枪伤）、三种拾取物。每只怪 4 帧动画。

**验收：灰度剪影测试**（`v-sprites-gray.png`）—— `grayscale(1) brightness(2.1)` 后仍能靠剪影区分六种：拖丝前倾 / 带背刺四足 / 放射腿圆身 / 低伏长吻 / 长着人手的团块 / 持炮大块头。**达标。**

**四个坑**

1. **画布尺寸 ≠ 视觉尺寸**：玩家画布 72px，身体只占中间约 30px，看起来比 56px 的僵尸还小 → 用 `ctx.scale(1.6)` 整体放大，代价是 `game.js` 布条坐标要按同系数对齐。
2. **深色叠深色会糊**：蓝灰玩家叠暗红地面，第一版是一团糊 → 加亮色护胸板 + 左上轮廓光拆开。
3. **顺序会毁细节**：守层者的结痂暗线画在七道伤口**之后**，`lineWidth 4` 把它们糊成一块红板 → 必须画在伤口之前。
4. **灰度滤镜要调**：第一版用 `contrast(1.45)`，画面全黑什么都没测到 → 改 `brightness(2.1) contrast(1.05)`。

**验证**：`smoke` PASS（新增 6 条断言）/ `determinism` 指纹不变 / `NO_PAGE_ERRORS` / `SPRITES_OK`。

**还没解决**：地面偏暗 + 血迹亮，混战时对比度不够。这批只保证"剪影可辨"，颜色层次留给 S6-E 统一调。

## 四之十五、S6-G 武器成长曲线修复（v0.3.2，2026-10-21）

两个"说不清为什么"的现象，其实是同一个函数的两处缺陷。

**① 捡完装备会回退到更弱的装备**：`giveWeapon()` 原来无条件 `p.weapon = id`——拿 tier4 轨道炮踩一把 tier1 手枪，主武器就被换成手枪。改成优先级判定：`更强 → 升级（旧枪退副武器槽）` / `槽空 → 进槽` / `同级 → 替换` / **`更弱 → 绝不降级，转补给（补满当前弹匣 + 25 残响）`**。

**② 三连发"消失"**：两因叠加——(a) 副武器槽空时捡到的枪进槽、主武器名不变，看着像没捡到；(b) `p.burstLeft` 换枪不清零，三连剩余发数会从**新枪**打出来（实测换成火箭筒后又补 2 发）。修法：升级优先于进槽、`resetBurst()` 在换枪/交换时调用、每帧校验当前枪是否还支持连发、HUD 的 `Q 切换 →` 常显。

**验证**：修复前后用复现脚本对比 4 个场景；`smoke` 新增 5 条断言；`PICKUP_OK`（含"弱武器转补给"截图 `v-pickup-salvage.png`）；`DETERMINISM_OK` / `NO_PAGE_ERRORS` / `PACK_VERIFY_OK`。版本 → **0.3.2**。

## 五、未验证项
