## 一、项目现状（一句话）

`CRIMSON ARENA` 是《血腥大地 / Crimsonland》的俯视角双手射击复刻原型，v0.1.0，纯前端 Canvas + 原生 ES Module，零依赖零构建，已有 9 武器 / 6 敌人 / 20 可叠加 Perk / 生存模式 + 6 个手工关卡，配套 3 个自动化验证脚本。

## 三、关键结论与方法

1. **架构选择正确，不必重做**：`update/render` 分离 + 数据表驱动，使 20 个 Perk、9 把武器能在 4000 行内成立。后续加内容只需扩数据表与 `sprites.js`。
2. **验证思路可复用**：`smoke.mjs` 用 DOM/Canvas Proxy 桩在 node 里跑 1.5 万帧，不需要浏览器就能抓运行时异常；`shoot.mjs` 用本机 Chrome 出真实截图。两者互补——前者验逻辑，后者验观感。
3. **机器人是平衡标尺**：完美瞄准 + 粗糙走位，90s 内 4 波 132 杀属合理区间；真人应更长。机器人跑关卡模式必死，说明关卡对"不会躲弹幕"的玩家偏难，这是设计意图还是问题，待定。
4. **历史踩坑（改代码前必读）**：
   - `randomWeaponDrop` 曾因排除当前武器后池子为空返回 `undefined` → `magSize(undefined)` 崩溃。已加空池回退，改动掉落逻辑时注意。
   - 加入 cam.zoom 后，鼠标世界坐标必须 `cam.x + (mouse.x - cam.ox) / zoom`；测试机器人不同步换算会偏移 30%，曾被误判成平衡问题。

## 四之二、D1 边缘威胁指示器（已交付）

**做法**：新增 `src/game/threats.js`，把"计算"与"绘制"拆开——`offscreenThreats(g,w,h)` 纯函数返回指示器数组，`drawThreatIndicators()` 只负责画。好处是无渲染环境也能断言（smoke 直接调纯函数）。

关键决策：
- 只在 `state === 'playing'` 时提示，暂停/升级/死亡/通关都不画。
- 按**到玩家距离升序**取近的，硬上限 8 个；距离越远透明度越低（0.95 → 0.3），避免远处刷屏。
- 指示器固定用威胁色（橙 `#ff8a3d` / Boss 红 `#ff2d3f` + 脉冲环），**不用敌人血液色**——毒蛛/蜥蜴的绿血（`#3f6b2a`/`#4c7a26`）在暗背景上几乎不可见，这是实测截图后改的。
- 先描 3.5px 深色轮廓再填充，保证压在地面暗部和血迹上都清晰。

**证据**：

```
$ node _staging/20261021_总控建制/verify-threats.mjs
指示器: { count: 5, angles: [ -45, 0, 180, -90, 90 ], bosses: 1 }
NO_PAGE_ERRORS
```

四个方向角与摆放完全一致（右 0°、左 180°、上 -90°、下 90°、Boss 右上 -45°）。截图：`shots/v-threats.png`（全景）、`shots/v-threats-right|left|top|bottom.png`（四边裁切放大）。

**回归**：`smoke.mjs` → `SMOKE_OK`，功能校验 PASS（新增 5 条断言）；战斗场景帧率 60.4，与改动前 60.5 持平（差 0.2%，在噪声内）。
