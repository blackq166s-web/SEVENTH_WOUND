## 一、项目现状（一句话）

`CRIMSON ARENA` 是《血腥大地 / Crimsonland》的俯视角双手射击复刻原型，v0.1.0，纯前端 Canvas + 原生 ES Module，零依赖零构建，已有 9 武器 / 6 敌人 / 20 可叠加 Perk / 生存模式 + 6 个手工关卡，配套 3 个自动化验证脚本。

## 二、已验证的基线（证据）

```
$ node tools/smoke.mjs
生存模式 90s : kills 132 / level 6 / wave 4 / hp 45 / state playing
生存模式 300s(不死): kills 540 / level 12 / wave 13 / maxEnemies 78
关卡模式     : kills 120 / level 6 / time 106s → dead（机器人不躲远程）
Perk 压测    : 17 级 / 12 Perk / 总层数 16 / 错误 0
功能校验: PASS
SMOKE_OK 无运行时异常
```

- 代码规模：4086 行（`game.js` 1010 行是唯一大文件，其余 ≤ 438 行）。
- 存档：仅 `localStorage['crimson_best']` 记录最高分（`game.js:52` / `:670`）。
- 手柄：**未支持**（全仓库无 `gamepad` 引用）。

## 三、关键结论与方法

1. **架构选择正确，不必重做**：`update/render` 分离 + 数据表驱动，使 20 个 Perk、9 把武器能在 4000 行内成立。后续加内容只需扩数据表与 `sprites.js`。
2. **验证思路可复用**：`smoke.mjs` 用 DOM/Canvas Proxy 桩在 node 里跑 1.5 万帧，不需要浏览器就能抓运行时异常；`shoot.mjs` 用本机 Chrome 出真实截图。两者互补——前者验逻辑，后者验观感。
3. **机器人是平衡标尺**：完美瞄准 + 粗糙走位，90s 内 4 波 132 杀属合理区间；真人应更长。机器人跑关卡模式必死，说明关卡对"不会躲弹幕"的玩家偏难，这是设计意图还是问题，待定。
4. **历史踩坑（改代码前必读）**：
   - `randomWeaponDrop` 曾因排除当前武器后池子为空返回 `undefined` → `magSize(undefined)` 崩溃。已加空池回退，改动掉落逻辑时注意。
   - 加入 cam.zoom 后，鼠标世界坐标必须 `cam.x + (mouse.x - cam.ox) / zoom`；测试机器人不同步换算会偏移 30%，曾被误判成平衡问题。

## 四、体检发现的问题

| 级别 | 问题 | 影响 |
| --- | --- | --- |
| 高 | 无 git 仓库，无任何可追溯版本 | 改坏无法回滚；阶段成果无版本索引 |
| 高 | 随机性不可控（`Math.random` 全库散落） | 同一用例两次结果不同（132 杀 vs 130 杀），平衡调优无法对比 |
| 中 | 视野外敌人无提示 | 混战中从背后被偷，玩家无法归因，体感"不公平" |
| 中 | 无位移技巧（无冲刺/翻滚） | 被围住时只能硬吃伤害，走位上限低 |
| 中 | 受击反馈弱（无顿帧曲线、无受击方向） | 打击感偏软，不知道伤害从哪来 |
| 低 | 无手柄 / 无触控 | 键盘鼠标限定 |
| 低 | `shots/*.png` 被 gitignore | 视觉回归无法留档 |
