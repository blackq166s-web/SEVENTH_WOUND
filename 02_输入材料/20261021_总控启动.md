# 2026-10-21 · 总控启动需求（原始输入）

来源：用户首次进入项目时的会话指令，本文件为只读留存，后续变更以新文件追加，不改历史。

## 定位

本会话命名为「总控」，负责持续推进本项目：维护状态、组织任务、验证成果、沉淀知识。项目可长期维护，每次围绕明确的阶段目标推进。

## 首次进入要求

- 先检查并复用现有结构，将长期规则精简合并到 `AGENTS.md`，保留已有有效规则，实质冲突再确认。
- 已有 `STATUS.md` 等同用途文件时沿用，不重复维护；缺失目录按需创建。

## 默认目录结构

```
AGENTS.md                 执行规则与权限边界
STAGE.md                  当前目标、完成标准、进展、阻塞、下一步及资料入口
01_阶段成果/当前总结.md    关键结论、方法、证据和遗留问题
02_输入材料/              原始需求与参考资料
03_项目实现/              代码、设计、配置等实际成果，内部按项目需要组织
_staging/YYYYMMDD_事项/    草稿与临时材料，同一事项复用目录
```

## 工作规则（原文要点）

1. 开始或恢复任务时了解项目规则、当前状态和本轮目标，自主选择方法、工具及任务组织方式，持续推进并做必要验证。常规可逆操作直接执行，只有关键歧义或超出授权时才询问，已有授权不重复确认。
2. 有实质进展时更新状态和当前总结，保留关键结论、证据、未验证项及下一步，写入后核验，避免重复记录。收到「保存阶段成果：名称」时，归档至 `01_阶段成果/YYYYMMDD_名称/`，包含当时的总结、关键文件或可追溯版本索引及适用条件。同名新增版本，不覆盖历史；保存不代表验收通过、项目结束或允许发布。
3. 复用现有结构，保留原始材料，重要成果及时从暂存区整理到合适位置。破坏性操作、生产变更、对外发布和实际付费须有明确授权，敏感凭据不写入普通文档、日志或仓库。回复简洁，说明成果、验证情况、文件位置和下一步，有必要时提出待决策事项。
4. 敏感信息管理：密钥、账号密码、Token 等统一存放于独立的 `SECRETS.local.md`，方便人工维护，禁止提交版本控制或对外泄露，Agent 仅在必要且授权时访问。

## 落地时的判断

- 项目已有 `README.md` + `docs/EXTENDING.md`，均属有效文档，保留不动，在 `AGENTS.md` 中作为入口引用。
- 项目无 `STATUS.md`，故以 `STAGE.md` 唯一承担状态职责。
- 代码已在仓库根组织好，`03_项目实现/` 仅建索引，不搬迁。
