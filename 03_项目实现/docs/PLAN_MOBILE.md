# 第七道伤移动端与体验优化开发计划

基线为 `v0.5.9`（`89ed535`）。先让玩家用手机浏览器触屏完成一局无尽生存，再打磨操作与战斗反馈，最后用可重复的真机对照优化性能。每阶段从上一阶段的验收版本继续。开发预览通过 HTTP 提供给真机，公开部署单独决定。

## 阶段一　手机横竖屏触控可玩

### 屏幕方向

横竖屏都能从菜单开局并打到结算。画布、HUD 和触控使用同一个视口。画面等比绘制，390 CSS 像素宽的触屏竖屏可横向看到约 480 个世界单位，横屏继续用 1.3 倍镜头。旋转只清除旧触点，保留对局及正在选择的刻印或武器。切后台时暂停战斗。关键控件避开刘海、圆角和系统手势区。[WebKit 安全区说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)

点按「竞技场」时请求浏览器全屏。浏览器拒绝或不支持时，游戏仍填满网页可用区域，可正常开局。iPhone 支持从已添加到主屏幕的网页应用直接启动。[Fullscreen Standard](https://fullscreen.spec.whatwg.org/#dom-element-requestfullscreen) · [WebKit 主屏幕网页应用说明](https://webkit.org/blog/13878/)

### 控件与输入规则

| 位置 | 行为 |
| --- | --- |
| 左下固定摇杆 | 控制移动方向，推得越远移动越快，推满达到现有移动上限。松手后移动输入归零，保留角色原有减速。 |
| 右下固定摇杆 | 向哪个方向推就朝哪个方向瞄准。超过死区后按现有武器规则持续开火，回中或松手后停止发起新攻击，并保留最后有效朝向。已触发的连发按原规则收尾，蓄力与空仓装填沿用原规则。 |
| 右上角与暂停面板 | 双竖线图标可随时暂停。暂停面板提供继续、静音、锁枪和结束本局，装备副武器后提供换枪并继续。刻印、武器对比及结算沿用现有可点按面板。 |

暂停图标有 44×44 CSS 像素的点击区，摇杆死区先用行程的 15% 做原型。HUD 的血量、弹药与威胁提示放在拇指区以外。第一阶段采用手动瞄准，保持选目标、扫射和蓄力的操作差异。

两支摇杆各自绑定一个 Pointer ID。拖出操作区后仍能跟踪原触点，抬起、取消或丢失捕获时释放该手指的输入。暂停、切后台、旋转、打开战斗面板和结算时释放两边的输入。恢复战斗需要新的触摸。仅在操作区拦截网页拖动手势，菜单和图鉴继续支持正常滚动。输入接入现有 `Input`、`Game` 和 `UI`，复用移动与射击逻辑，主循环继续使用固定步长。[W3C Pointer Events](https://w3c.github.io/pointerevents/#pointer-capture)

### 验收

- **一局跑通。** 在 iPhone 和 Android 的 Chrome、Edge 上验证横竖屏开局、对局中旋转、至少一次升级和武器选择、正常死亡、结算与重开。记录点击开局后的全屏行为，iPhone 另验证从主屏幕打开。用可重复场景覆盖重掷、装备、把枪放入已解锁的副武器槽、放弃、空仓自动装填、暂停菜单换枪、锁枪与静音。
- **动作和中断。** 双指同时移动和开火，交换先按下的手指，任意一指抬起时另一指仍可用。拖到摇杆外、系统手势取消、握持时旋转或切后台、按着开火时弹出选卡，回到战斗均没有卡键、误射、误点或跳过选择。暂停期间计时和敌人位置不推进。首个有效交互后验证音效和静音，地址栏伸缩、横屏两个方向都检查控件、安全区和卷动。
- **界面与回归。** 模拟 667×375、844×390 横屏和 390×844 竖屏，实际布局以可见视口为准。关键 HUD 与控件无覆盖，刻印与换枪按钮可达，图鉴可滚动。桌面 Chrome 或 Edge 验证键鼠开局、移动、瞄准、射击、冲刺和各面板快捷键。留真机型号、系统与浏览器版本、测试结果和录屏或截图。冒烟通过，浏览器截图验证输出 `NO_PAGE_ERRORS`，单文件打包通过并用 HTTP 检查打包版开局。

## 阶段二　手感与战斗可读性

用早期普通战、密集混战和守层者三个固定种子测试场景调校。先调摇杆死区、瞄准稳定性、场地可见范围，再调枪口与命中反馈、受击方向、敌弹与经验的区分和自动装填提示。优先修复重复出现的误触、看不清和操作反馈延迟。武器、刻印和波次规则以阶段一版本为参照，确需调数值时单独记录目标和前后结果。

### 验收

- **可操作。** 在相同场景重复验证左手持续移动、右手追踪目标和自动装填后恢复射击。摇杆心附近轻触不会误开火，推离死区后方向稳定。手枪、三连点射、轨道炮和激光各走一遍，验证按住、松手、蓄力和换枪行为。
- **可读。** 至少三位首次上手的玩家试玩，覆盖两个手机平台。至少两位无需口头提示即可开局、边走边射并选一次刻印。让三位玩家各看同一段混战回放，至少两位能正确指出敌弹、经验和一次受击来向。发现可以稳定复现的操作阻断时修正后重测。
- **有记录可复测。** 保存同种子、同设备的前后片段与问题复测表。保留桌面键鼠回归和冒烟结果。涉及视觉的改动保留截图与 `NO_PAGE_ERRORS`，涉及随机源或玩法数值的改动补跑 `determinism.mjs`。

## 阶段三　性能测量与优化

扩展并运行 `tools/fps.mjs`，建立普通战和后期密集战两组负载，密集战覆盖守层者、敌弹和粒子同时出现的画面。固定种子、武器与刻印组合、输入轨迹和面板选择规则，自动处理刻印及武器面板，核对实际局内时长和敌人、子弹、粒子数量，防止把暂停面板当作作战样本。

记录前台帧间隔、掉帧长尾和模拟更新耗时，用浏览器性能追踪定位渲染开销。开始跑前选定实际的 60 Hz iPhone 和中档 Android 测试机。固定设备、浏览器、刷新率、画质、供电和预热条件，避免后台与过热干扰。只纳入有效战斗区间，每场景采样至少 60 秒，基线和候选版本同场交替测三组，报告每组结果和中位数。旧的无头平均 FPS 仅作诊断线索。

根据测量结果安排改动。渲染压力优先检查画布像素比、粒子和全屏效果，保留敌弹与命中等必要提示。模拟压力优先检查敌人分离及子弹碰撞，任何检索优化都要验证碰撞次序、命中与固定种子结果。

### 验收

- **真机目标。** 两台 60 Hz 验收机在普通战和密集战中，三次测量取中位数，帧间隔 P95 不高于 20 毫秒，超过 50 毫秒的帧间隔占比不高于 1%。P95 表示 95% 的帧间隔在该值以内。这是计划目标，先实测阶段二验收版本再判断差距。
- **收益与回归。** 若基线超标，逐项提交同场景前后结果，观察超标指标是否达到目标。若基线已达标，保留基线和压力场景证据即可。涉及模拟的等价优化，用同一输入轨迹比对关键状态、命中、击杀、波次和得分，跑冒烟与确定性检查。涉及画质的优化，用对照截图和真机完整一局验证触控、敌弹对比度和 HUD 可读性。
- **验收记录。** 保留脚本参数、设备信息、场景密度及原始数据。未达标时按机型与场景记录差距，说明瓶颈和当前可用的画质设置，阶段保持未验收。

## 开工后的第一个切片

同一个本地 HTTP 版本接入双摇杆，验证可同时移动、瞄准和射击，松手能释放输入，桌面键鼠可以正常开局。跑通后再接旋转与暂停恢复、面板触控和整局真机验收。
