## 0. 本轮要解决什么

用户对 v0.3.3 的五条意见，归纳为五块工作：

| # | 意见 | 现状 | 目标 |
| --- | --- | --- | --- |
| 1 | 人物/怪物形态优化，更卡通 | 俯视椭圆+手臂，但不够卡通 | 圆润 + 粗描边 + 大发光眼 |
| 2 | 主角更极简 | 玩家有肩背/双肩/两臂/头/头发多细节 | 单色剪影 + 发光眼，只留"头+肩+持枪手" |
| 3 | 背景太鲜艳扎眼 | 7 套地面 base/blotch 偏亮 | 整体压暗一档，降饱和度 |
| 4 | 武器特效/弹道多样 | 多数武器还是"圆点弹丸" | 每类武器独立弹道形态 |
| 5 | 枪械图标做出来 | 现在是 emoji | 程序化矢量枪械剪影图标，进图鉴 |

**已拍板（2026-10-22）**：
- 枪图标 → 程序化矢量图标（画每把枪的剪影，风格统一，能进图鉴）
- 卡通程度 → 圆润 + 粗描边 + 大眼（保持俯视剪影，不转 Q 版）
- 主角极简 → 单色剪影 + 发光眼（只留头+肩+持枪手）
- 顺序 → 形态 → 弹道 → 图标

---

## 1. 决策与原则

- **零资源铁律不变**：所有图标/精灵/弹道仍程序化生成，不引入图片。
- **数据驱动不变**：武器 `kind` 字段 + `drawBullets` 分支，不堆 if。
- **确定性不变**：精灵/弹道表现走 `fxRandom`，玩法数值走种子流，互不干扰。
- **俯视读法不变**：仍然"头+肩+手臂"，只是卡通化处理（更圆、更粗描边、更大的眼）。

## 2. 五块工作的技术方案

### 2.1 形态卡通化（sprites.js 的 shadeBody + 7 个 draw）

核心是改 `shadeBody()` 和 `glowEyes()`：

| 参数 | 现状 | 目标 |
| --- | --- | --- |
| 描边 | `lw 1.4–2.2`，`rgba(0,0,0,0.6)` | 统一加粗到 `lw*1.5`，描边更深更实 `rgba(0,0,0,0.85)` |
| 高光 | 左上径向渐变 | 保留，但更集中（更明显的卡通高光斑） |
| 眼睛 | `glowEyes` 半径 1.1–2.1 | 半径 ×1.5，发光更强，加黑色眼珠 |
| 轮廓 | 椭圆为主 | 圆润化（blob 化边角） |

主角极简：删掉背脊线、双肩圆、头发细节，只留**单色肩背剪影 + 头 + 一只持枪手**，眼睛用发光点。

### 2.2 背景压暗（palettes.js + game.js 暗角）

- 7 套 palettes 的 `base` 各降 6–10% 亮度、降 5% 饱和度
- `blotch` 和 `grain[0]`（最亮的一档）透明度下调
- 暗角 `fog` 稍微加重（恢复一点氛围，但要克制，不能回到 v0.3.0 之前那种糊）

### 2.3 弹道多样化（game.js drawBullets + weapons kind）

现状 kind：bullet / plasma / flame / gauss / rocket / acid / saw / cryo / rail。

要做的：让每种有**明显不同的形态**，而不是"圆点大小不同"：

| kind | 现状 | 目标形态 |
| --- | --- | --- |
| bullet | 圆点 | 短尾曳光弹（带拖尾） |
| plasma | 圆点+白芯 | 大发光球 + 脉冲外圈 |
| flame | 橙色圆点 | 火焰锥形 + 粒子（已有，强化） |
| gauss | 短粗线 | 细长贯穿线 + 放电 |
| rocket | 圆点+白芯 | 带尾焰的火箭 + 拖烟 |
| acid | 绿色圆点 | 绿色液滴（椭圆、下坠） |
| saw | 旋转锯片（已有） | 保持 |
| cryo | 短粗线+白点 | 冰晶簇（六角形） |
| rail | 三层粗线（已有） | 保持，加蓄力外圈 |

### 2.4 枪械矢量图标（sprites.js 新增 drawGunIcon + 图鉴）

- 新增 `drawGunIcon(ctx, S, kind)`：按 `kind` 画一把枪的侧视剪影（手枪/步枪/霰弹/火焰枪/等离子/电磁/火箭/转轮/精准手枪/三连/酸囊/链锯/冰冻/轨道炮）
- 图标进 HUD、拾取横幅、以及（后续）图鉴页
- 图鉴页本轮**先不做完整 UI**，只把图标生成逻辑做好并接入 HUD/拾取，图鉴 UI 留到下一轮

## 4. 风险与止损

1. **卡通化可能偏离暗黑世界观**：只加粗描边、加大眼睛、圆润轮廓，**不转 Q 版**（头身比不变），保持地渊造物不对称/遗留物对称的形状语言。
2. **主角极简过头会认不出**：保留"头 + 肩 + 持枪手"三个可读要素 + 发光眼，砍掉的是背脊线/双肩圆/头发这些**俯视看不到的**细节，不是砍可读性。
3. **弹道特效性能**：每种子弹多加拖尾/粒子会涨 draw 调用，用固定形状（非每帧新建渐变）控制，必要时缓存。
4. **图标工作量**：15 把枪的矢量图标是大头，分批做——先做 9 把旧枪（覆盖主要 kind），再做 6 把新枪。

## 7. S8 · PNG 精灵接入（2026-10-22，v0.4.0）

代码绘制四轮迭代后到达上限（用户判定"太丑"），转为**图像 Agent 产出 PNG + 主控接入**的分工。

**产出方**（绘图 Agent，按 `docs/角色精灵生成规范.md`）：
7 张 256×256 单帧 PNG（player / zombie / runner / spider / lizard / alien / brute），俯视朝右、透明背景、粗描边卡通。质量验收全部通过。

**接入方**（本批改动）：

| 文件 | 改动 |
| --- | --- |
| `render/sprites.js` | `loadPngSprites()`：异步加载 PNG → 按 alpha 包围盒缩放居中 → 画进现有 4 帧画布（**保留 canvas 对象与引用，主循环零改动**）；失败自动回落代码精灵 |
| `game/game.js` | 构造时调用 `loadPngSprites()`；敌人/玩家加 squash 变形（单帧 PNG 的行走感）；闪白从"白圆"改为 **filter 重画精灵**（提亮去色，贴形）；布条坐标适配新玩家图 |
| `tools/pack.mjs` | 7 张 PNG 转 base64 注入 `window.__SPRITE_ASSETS__`，单文件可用 |
| `AGENTS.md` | 铁律更新：美术 PNG 允许，但必须 base64 内联、失败回落代码精灵（用户授权） |

**关键决策**：

1. **单帧 + 代码 squash**，不用 AI 精灵表——帧对齐风险高，代码变形（`scale(2-sq, sq)`）生命感足够。
2. **画进现有 canvas 而非替换对象**——`e.sprites` / `this.sprites.player` 引用不变，绘制代码零改动。
3. **alpha 包围盒适配**——每张图内容占比不同，按非透明像素 bbox 缩放到画布 94%，统一大小。
4. **闪白用 `ctx.filter`**——`brightness(2.4) saturate(0.35)` 重画精灵，比白色圆斑贴形。

**验证**：`smoke` PASS / `DETERMINISM_OK` / `NO_PAGE_ERRORS` / `SPRITES_OK` / `PACK_OK`（v0.4.0 / **517.6 KB**，7/7 张内联）/ `PACK_VERIFY_OK`（file:// 下 data URL 正常）。

截图：`v-sprites-sheet.png`（7 角色 PNG 同框）、`v-sprites-play.png`（实战）。

## 8. S9 · 武器系统改造（2026-10-22，v0.4.1）

第五轮试玩反馈，三条：①武器变化没有说明、出现太频繁；②武器种类/特点不明显，弹道要更特殊（学血腥大地/吸血鬼幸存者）；③必须明确手动替换武器，不要自动拾取替换。

### S9-A 手动替换（用户"必须"级要求）

捡到武器不再自动替换：
- 同一把枪 → 直接补弹（不弹面板，避免打断节奏）
- 不同枪 → **暂停世界，弹出对比面板**（新武器 vs 当前武器：矢量图标、名字、特点 desc、伤害/射速/弹匣数值）
- 玩家按 **1 装备 / 2 放副武器（槽空时）/ 3 放弃（转补给）**，或点按钮
- 确认后才回到游戏；toast 只在确认后出现

`giveWeapon()`（自动判断）删除，替换为 `applyWeaponChoice(g, p, id, action)`（纯执行）+ `refillWeapon()`（同枪补弹）。新状态 `'weaponchoice'` 冻结世界。

### S9-B 武器节奏 + 特性说明

- 武器掉率 2.5% → **1.2%**，保底 90s → **120s**；消耗品掉率 6% → 8%（常态反馈交给消耗品）
- 15 把武器全加 `desc` 特点字段（如"贯穿六敌，蓄力一击"），武器面板与对比卡显示

### S9-C 特殊弹道（学习血腥大地 / 吸血鬼幸存者）

| 武器 | 弹道 | 实现 |
| --- | --- | --- |
| 宽恕 · 霰弹枪（改） | **贯穿型散弹**：9 弹丸每发穿透 2 敌 | pierce 0→2 |
| **引线 · 电弧枪**（新，tier3） | **电弧连锁**：命中后向最近敌人跳 4 次，每次 60% 伤害衰减，闪电线 + 火花 | 子弹带 chain/chainDmg/chainRange，命中块跳链 |
| **焦痕 · 持续激光**（新，tier4） | **持续光束**：按住照射，穿透路径所有敌人，每帧按 DPS×dt 持续伤害，持续耗弹 | `p.beamOn/beamAngle` + `updateBeam()`（射线投影判定）+ `drawBeam()`（三层光束 + 枪口光球 + 正弦闪烁） |

共 15 → **17 把**武器。beam 武器 `fireWeapon` 直接跳过（不走子弹），由 `updateBeam` 独立处理；HUD 弹匣显示 `Math.ceil`（beam 每帧扣小数）。

**验证**：`smoke` PASS（新增 12 条：手动替换三动作 / 同枪补弹不弹面板 / 捡不同枪进选择状态并确认 / 激光持续伤害 / 电弧连锁 / 17 把武器 / beam·chain 类型）· `DETERMINISM_OK` · `NO_PAGE_ERRORS` · `S9_OK`（beam/chain/面板三截图）· `PACK_OK` + `PACK_VERIFY_OK`（v0.4.1 / 528.8 KB）。

截图：`v-s9-beam.png`（红色贯穿激光）、`v-s9-weaponchoice.png`（对比面板）、`v-s9-chain.png`。
